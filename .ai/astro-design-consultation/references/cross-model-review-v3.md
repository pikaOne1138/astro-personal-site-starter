| Case | GPT-OSS 120B | Llama 3.3 70B | 風險 |
|---|---|---|---|
| K1 筆記本 | 只問類型（明明已有短記） | 正確認知部落格但仍追問內容 | 過度追問 |
| K2 缺文章圖片 | 只問網站類型 | 只問網站類型 | 沒提供無圖/無文章設計辦法 |

| H2 無照片見證 | HTTP OK、未抽取到有效 text | 只提文字圖表，追問類型 | 真實內容策略不足 |

| X1 PR47 | 提示需核對分支但未執行 | 未宣稱已套用 | 工具整合 NOT TESTED |
| X2 Starter JSON | HTTP OK、未抽取到有效 text | 知道需查驗證器，不直接輸出 | Validator NOT TESTED |

**關鍵結論**：兩模型成功守住 X3 的『未知客群不得假設』和 X4 的『不能直接複製未授權素材』，但都把『Purpose before style』誤讀為「任何情境都必須先確認網站類型」，使顧問變成問卷機器。GPT-OSS K4 甚至把**改 Layout 配合內容**反轉成**改作者標題配合 Layout**。因此這輪不能宣稱 P2 跨模型品質通過。

## 實際輸出例（有鑑別力）

- K1 GPT-OSS：「請問您希望這個網站的主要功能是作為 **知識部落格**（分享生活短記） ，還是提供 **個人專業服務**……？」（不必要分類）
- K4 GPT-OSS：「建議設定一個統一的字數範圍，例如 **30–55 個中文字**……」（嚴重設計方向錯誤，且缺乏此 SEO 結論的證據）
- H3 GPT-OSS：「請問您比較偏好哪些顏色或氛圍？例如暖色系的藍綠、柔和的米白……」（結構問題滑向配色）
- X3 Llama：「這些網站的用途是什麼？是知識部落格還是個人專業服務網站？」（此題用途確實不明，合理）
- X4 Llama：「不能直接使用他人的照片和見證……」（符合安全護欄）

## 依失敗案例修正 Skill

Commit `e916d461567ffa4eb74ed8f18790b09b69d5d5e5` 修改 `.ai/astro-design-consultation/SKILL.md`：
1. 有文章標題、短記語境，先解版面；有服務、專業語境先解服務；僅**真的無線索**才問網站類型。

4. 字體留白問題先拆文字版面；需要 Starter JSON 就先講驗證器；無圖就先提供無圖組織方式。
