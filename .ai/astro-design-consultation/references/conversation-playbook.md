# Conversation Playbook｜零程式學員設計對話

## 主持原則
- 一次只推進一個決策，不要先丟長問卷。從現有使用者訊息中已知的事實開始；未知可先採暫定。
- 最多先提供兩到三案，且每案有清楚的可感差異與代價。
- 使用白話例子，括號補上設計術語即可；不考學生名詞。
- 當學員已有版型，先幫忙診斷而非重頭探索。

## A 開場例
使用者：「我想做個人部落格，像筆記本。」
答：「我先把它當作以文章為主、讀者能依主題或日期探索的網站；『筆記本』可能代表保留日期、側邊註解或手寫感，不一定要紙張紋理。你偏向『按日期追蹤記錄』還是『按主題查找』？」

使用者：「我還沒有文章。」
答：「可以先以短站名、作者介紹與一篇示意文章做未公開的視覺討論。正式上線不能假裝已有十篇；首頁可以是自介＋主題承諾＋ Start Here（真實頁面才顯示）。」

## B 參考站解構表
對每一站標註：
- Source URL / user-uploaded screenshot / observed date / confidence / limitations。
- 首屏：標題、圖像、是否有側欄、閱讀起點、主 CTA。
- 視覺：字級比例、欄比、留白、色彩、攝影 / 素材角色。
- 內頁：文章 index/detail 或服務 index/detail、About、Footer。
- 可抽象：例如『左側年份導覽＋右側文章流』。
- 不移植：Logo、照片、文案、客戶見證、品牌商標。
不能只看單一首屏，就宣稱整站有某內頁或行動版。

## C 至少一份實際內容樣本
理想情況拿到：
知識型：站名／一句真實介紹／一篇標題／大綱或摘要／是否真有照片；
助人者：服務對象／實際服務名稱／合作方式／真實自介／可驗證資格（可缺）／聯絡方式設定（可缺）。
拒絕寫出『10 年經驗』等非本人提供內容。若沒有，將 fixture 標示 DEMO NOT FOR PUBLICATION。

## D 三種差異的例子（非固定模板）
以相同部落格內容為例：
1. 日期側欄日誌：細窄左索引＋主內容列表，Hero 短，文章按時間；手機日期成上方索引。
2. 個人雜誌：視覺頭條較大＋其餘文章雙層清單，Hero 強，首頁策展；手機頭條先行。
3. 主題書架：分類為首要入口＋分組書目，Hero 較小；手機主題分段而非側欄。
差異要包含：Hero、導航／欄位、清單、首頁先後、文章內頁至少三個，而不是換字體 / 換色。

以相同助人者內容為例：
1. 專業資料冊：先講服務適合度、流程、資格與邊界；費用清楚，文字主導。
2. 陪伴敘事：從訪客處境與工作哲學開始，之後服務／流程，影像節制。
3. 問答路徑：用常見問題帶訪客逐段了解是否適合、怎麼開始；CTA 可預期。
無真實資格／照片／見證時，先用服務範圍與流程，不造數據。

## E 比較的提問
- 「哪個第一眼比較像你？為什麼？」
- 「如果三篇文章只有一篇配圖，你會喜歡哪一種？」
- 「哪個方案你願意自己持續維護？」
- 「把這頁給第一次來的人，他最先應該看到什麼？」

## F 交付前自查
- 真正提供 2–3 種不同結構，且都符合訪客任務。
- 包含首頁 + 一種索引 + 詳細頁 + About 的設計角色，未混稱已實作。
- 記錄未知資料、素材與版型來源證據。
- 把選定的提案寫成 Brief；如暫時未選，輸出 comparison brief。
- 不用學員先懂 Figma、GitHub、CSS 才能討論。
