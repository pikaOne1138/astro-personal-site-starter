# v0.2 協作與合併紀錄

## 目標

把 v0.1 的六個單頁視覺 prototype，升級成真正的 Astro 多頁 Starter：

- 2 種網站任務：Knowledge / Helper
- 3 種視覺人格：Paper / Morning / Studio
- 6 組可獨立瀏覽的網站入口
- 共用底層資料、元件與設計規則，不複製六份程式碼

## Branch 分工

### `v0.2-multipage`（本分支）

負責：

- 多頁 routing
- 三種 Navbar 系統
- sitemap / route data
- About / Articles / Topics / Start Here / Resources
- Services / First Visit / FAQ / Booking
- Article detail / Service detail
- multipage layout CSS
- 架構文件

主要檔案：

- `src/site-map.ts`
- `src/components/SiteNav.astro`
- `src/components/MultiPage.astro`
- `src/pages/[kind]/[theme]/[page].astro`
- `src/pages/[kind]/[theme]/articles/[slug].astro`
- `src/pages/helper/[theme]/services/[slug].astro`
- `public/v02.css`

### 另一條首頁／元件庫工作

建議負責：

- 首頁 section 元件
- UI component library
- component preview / showcase
- 卡片、按鈕、Badge、Callout、Testimonial 等可組合 UI
- 首頁視覺 refinement

若需要修改 `src/components/DemoPage.astro`，合併時保留：
- `<SiteNav kind={kind} theme={theme} current="home" />`
- 其他首頁 sections 可以自由重構。

## 合併原則

1. 不直接把六個版本複製成六套元件。
2. 首頁是入口，不承擔所有詳細資訊。
3. Navbar 必須導向真實頁面；首頁內仍可保留 section anchor 作為局部 CTA。
4. Component Library 應吃既有 design tokens，不另外發明一套視覺系統。
5. 若元件庫與 multipage branch 同時修改 `DemoPage.astro`，手動合併；不要用其中一方整檔覆蓋。
6. 先保持 Astro 靜態網站範圍；外部預約、表單、newsletter 用整合，不建立 CRM。
