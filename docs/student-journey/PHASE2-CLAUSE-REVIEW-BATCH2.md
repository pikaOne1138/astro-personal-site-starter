## 主要不一致／人工判讀需求

1. `docs/brief-handoff/README.md`：13 段 Markdown Design Brief 和 StarterPlan JSON **是兩種資料契約**；不能把完成 Design Brief 誤說成直接可匯入 Site Brief。
2. `EXPANDED-LAYOUTS.md`：12+13 個 Layout 方向的可組裝與 Ready 有區別；不同 Adapter 的路由／內容契約要讀原檔，不能濃縮為「全部可直接上線」。
3. `SECTION-PATTERNS.md`：`targetPage` 在首頁用 `/`，其他頁用 navigation ID 而非 URL；只支援既定 `insertAfter` 值，無效位置應拒絕匯出；可選區段缺素材時可以移除，不應編造假資料。
4. `OWNED-MEDIA.md`：圖片可內嵌或使用授權的本地檔案；品牌圖片是選填，不能讓學員先提供技術路徑；區別 Logo contain、Hero cover/contain 與裁切位置。
5. `MEDIA-REPLACEMENT.md`：來源展示媒體不得推定有重製授權；不能把外部 URL 或 Demo 資產當正式可商用素材，無媒體播放器需明確標示。
6. `START-BUILD-PROMPT.txt`：屬 Builder ZIP＋Site Brief 的正式建站指令；不能取代跨路線的 START-HERE，也不能把純聊天模型說會寫程式當成具備 GitHub/Build/Preview 權限。
7. `UPSTREAM-SOURCES.md`：描述打包源與交付邊界；如實際打包腳本已更新，該文件應與腳本比對，不能單靠文案推定檔案存在。
