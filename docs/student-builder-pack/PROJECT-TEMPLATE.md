## 8. 維護規則

1. 第一次討論先以可確認的回答逐步補充；未回答的欄位保留「待確認」。
2. Site Brief JSON 是建站規劃的結構化輸入；AI 可依其**已驗證**內容更新本文件，但不將 JSON 當成已實作證據。
3. 只有品牌定位、受眾、設計取捨、網站架構、部署選擇等**長期決策**需要更新這裡。每日文章新增、單純改字與小幅 CSS 調整由內容檔與 Git 歷史記錄。
4. 修改本文件前先查看現有內容與使用者尚未提交的變更；絕不可用 ZIP 模板或重新匯出覆蓋既有決策。衝突時列出差異，詢問學員。
5. 所有寫入都要區分「學員已確認」「AI 提案」「待確認」；AI 不得替學員批准選擇、發布或 Merge。
6. 換 AI、換電腦或開新對話，先閱讀 `AGENTS.md`、本文件與實際 Git／原始碼狀態，再接續工作。
