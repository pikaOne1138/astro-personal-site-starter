# PR49｜對話品質驗證報告（第一輪）

- 日期：2026-10-14
- 範圍：`astro-design-consultation` 初版，13 種 scenario fixtures
- **方法**：依 Skill 原文由同一位審查者撰寫情境模擬的「預期良好回覆」，並逐項檢查可理解性、內容忠實、結構差異、問答節奏與跨 Skill 邊界。**不是**以另一個獨立 Agent 載入 Skill 並測得的真實回覆；不是 A/B benchmark，亦無學員參與。
- 解讀：`DESIGN-REVIEW OK` 是案例與規則在人工設計審查上自洽；`OPEN RISK` 是實際模型或真人互動未驗證。**沒有填寫 13/13 模型 PASS**。

## 評估尺度

1. 第一輪可理解性：不用學員先了解 Hero、IA、Tokens、Astro。
2. 提問節奏：只問一個必要問題；能直接回應時不可只問問題。
3. 真實內容：未提供資料不造文章、見證、證照、人物照片、服務成效或成功表單。
4. 差異品質：當需求是方向比較時，候選的首屏、導航/閱讀動線、內容呈現、內頁至少三項不同。
5. 可行交接：規格和 StarterPlan 分開；未核實 PR47 readiness 不宣稱 Ready。
6. 回應與修正：遇到「都不喜歡」能改構圖，非只換皮。

**結果**：13 個 fixtures 都找到合理、符合任務邊界的範例回覆；這只能支持「規範設計上可操作」，不能支持「AI 實際執行 13/13 通過」。最明顯風險是 Skill 原文缺少第一輪回覆長度和不強制多方案的限制，已新增具體護欄。

## 三組多輪對話推演（人工模擬）

### M1：無程式背景＋模糊偏好→選方向
**學員**：我想要一個看起來很舒服的部落格，但不要太制式。

**顧問**：先拿「讀者能舒服閱讀你的文章」作為目標。可以走「日期側欄日誌」（左側日期、右側文章）或「單篇大字雜誌」（先一篇主文章，再往下翻其他文章）；兩者最大差別是讀者從時間找文章，或由你先推薦哪篇。你比較想強調哪一個？

**學員**：我想要文章主題比較清楚，但不要很像新聞網站。

**顧問**：那調整為「主題書架」：先看到幾個你真的寫的主題，再進到文章。首頁不用新聞站那種多張等寬卡；文章詳頁保持窄閱讀欄。你目前有兩三個已經寫過的主題嗎？

**觀察**：第二輪依新資訊改變構圖，不重複推最初兩案。**待測**：真實模型是否能連續記住已排除的「新聞感」。

### M2：助人者不能造信任資料
**學員**：我做催眠，但沒證照也沒客戶見證，想要高級一點。

**顧問**：可以用真實的服務內容與工作方式建立可信度，不能填假證照或假評語。建議先看兩種：文字清楚的「服務說明冊」，或有呼吸感的「陪伴敘事」。前者先回答服務方式與界線；後者先說你如何理解來訪者，再提供服務流程。你比較想讓第一次來的人先看到哪一種？

**學員**：我想讓他覺得很安心，不要銷售感。

**顧問**：那先用陪伴敘事，但聯絡入口仍明確。首屏是一句不保證療效的定位與一段簡述；第二區清楚說「適合什麼人／不適合什麼需求」；第三區是真實流程。沒有見證也不會空出假的推薦卡。

**觀察**：情感訴求沒有推導出虛假可信度，沒有用顏色代替資訊架構。**待測**：是否理解不同專業領域的語言合規。

### M3：拒絕三方案並收斂
**學員**：你給我的三個版本我都不喜歡，都是首屏大字加三張卡。

**顧問**：你指出的是同一種構圖，不是配色問題。這輪不再給三張卡。我改成一種「索引式首頁」：上方短介紹，左側固定主題目錄，右側直接出現文章列表；手機主題目錄移到標題下方。這樣讀者一進來就看到內容本身。你覺得這樣比較接近，還是希望首頁先呈現你這個人？

**學員**：這個比較對。

**顧問**：我先記錄決策：選索引式首頁、不採用三卡、不用巨大 Hero；接著再檢查文章詳頁是否能保有相同的索引語言。

**觀察**：應承認批評、改結構並更新決策，不要繼續強推原案。**待測**：真實學員能否理解這些差異。

## 發現問題與已調整

1. **原版第一則回覆可能太長**：因「流程」與「13 欄 Brief」太完整，容易一次全倒給新手。已在 `SKILL.md` 明確規定一輪只推進一個決策；先白話摘要，技術細節留交接。
2. **原版的 2–3 案要求可能過度觸發**：現在只有使用者要比較方案時才提出多案；若只想評價一頁，直接評論該頁。
3. **原版缺少『三案都不喜歡』的恢復規則**：現在要求換結構，不能只換色。
4. **原版未明確處理自相矛盾的要求**：如「沒有照片卻要大量本人形象照」，先指出代價與選項，不能偽造。
5. **原版『成功』定義可能與真實測試混淆**：追加情境模擬／獨立 Agent／真人學員三種證據層級，不用桌面審查冒充實測。
