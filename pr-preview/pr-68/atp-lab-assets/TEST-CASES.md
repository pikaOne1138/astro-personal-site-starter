# ATP A/B/C 對照實驗：共用情境
本文件不是學員真實內容。**測試 1**：三組只收到同一段自然語言需求，不預先給 Site Brief；A 依完整既有學員流程操作，B 用 AI 訪談＋精簡 ATP，C 用 AI 訪談＋獨立 Skill 從零建立 Astro。**測試 2**：才使用相同規劃器版本與完全相同的 Site Brief JSON 給 A/B/C，比較純實作層差異。

## 情境 K｜知識部落格
網站名稱「慢讀觀察」，以閱讀筆記、個人觀點與主題文章為主。目標訪客是想建立閱讀習慣的讀者。首頁主 CTA 為「閱讀文章」，不建立未串接的電子報服務。提供首頁、文章列表、兩篇範例文章（明確標 Demo）、關於頁。內容與人名皆為測試資料，不得當作真實個人品牌。

## 情境 H｜助人者
網站名稱「清楚對談」，以個人職涯教練服務的資訊介紹為主。首頁主 CTA 為「了解合作方式」。提供首頁、服務說明、合作流程、關於、FAQ、聯絡方式（沒有真實端點時標待設定）。不得虛構證照、客戶見證、價格或成功預約。

## 控制條件
- 三組相同模型、版本、工具能力與時間預算。
- A 使用完整現行資料包；B 使用精簡 ATP；C 使用空白 Astro + Skill。
- 測試 1 三組同一原始需求，不預先給 Site Brief；測試 2 三組同一 Site Brief JSON。兩次都禁止某組額外接收未規定資料。
- 運行環境必須能寫檔與執行 Node；如果不能，記錄能力差異，避免誤當架構品質差異。
- 一律 Branch/PR → Build → Preview → 人工驗收，不許自行正式發布。
- 每組都保留實際指令、錯誤、修正次數與結果證據。分開記錄測試 1（從零訪談）與測試 2（固定 Brief）。
