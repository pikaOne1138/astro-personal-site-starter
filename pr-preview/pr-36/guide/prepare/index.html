前置準備開始建置

PREPARATION / 完全不會程式也能照做

先準備好，再開始建置。

建立 GitHub 帳號、連接 AI、準備網站內容與品牌圖片。

GitHub 是什麼？ ↓註冊並登入 GitHub。建立自己的倉庫 ↓建立網站倉庫。讓 AI 存取倉庫 ↓授權 AI 存取你的倉庫。網站內容訪談 ↓下載訪談包，與 AI 討論內容。Logo、Favicon 與網站圖片 ↓用 AI 設計 Logo、favicon 和圖片。GitHub Pages 設定 ↓選擇 GitHub Pages 時完成。Cloudflare 事前準備 ↓不使用 GitHub Pages 時可選。

01｜認識 GitHub：不用先學會寫程式

  1. 開啟 GitHub 註冊 ↗；若已有帳號，就直接登入。
  2. 登入後，確認右上角頭像選單能看到自己的帳號名稱。
  3. 記下自己的 GitHub 帳號名稱。
找不到按鈕？截圖給 AI，請它教下一步。截圖前遮住敏感資訊。

02｜建立第一個 Repository

  1. 開啟 GitHub New repository ↗。
  2. 確認 Owner 是自己的帳號。
  3. Repository name 輸入英文簡短名稱，例如 my-personal-site。
  4. 選擇 Public（公開）或 Private（私人）。第一次建站，想簡單免費：建議選 Public，網站原始碼也會公開。想保留 Private，可使用符合資格的 GitHub 付費方案搭配 GitHub Pages，或改選 Cloudflare Pages 等支援私人倉庫的託管平台。
  5. 勾選 Add a README file，其餘保持預設。
  6. 點 Create repository。看到 你的帳號/my-personal-site 的 Code 頁，代表倉庫建立成功。

不會操作？複製提示詞給 AI。

請一步一步教我在 GitHub 建立個人網站倉庫。每次只給一個步驟，告訴我要按哪裡、成功後會看到什麼。如果介面不同，請我截圖給你確認。不要要求密碼或驗證碼。

03｜讓 AI 真正有權限讀寫你的倉庫

先在 AI 網頁連接 GitHub，再開啟 Installed GitHub Apps 管理頁 ↗。

  1. 找到這次使用的 AI App，例如 ChatGPT Codex Connector 或 Claude；按 Configure。
  2. 向下找到 Repository access，建議選 Only select repositories。
  3. 按 Select repositories，把剛剛建立的網站 Repo 加入清單，再按 Save。
  4. 回到 AI 對話，要求它讀取該倉庫的 README.md，並確認是否能對指定 Repo 建 Branch/PR。
找不到 App？回 AI 工具重新連接 GitHub。新倉庫也需要加入授權清單。

04｜讓 AI 訪談你，寫出網站所需內容

用訪談包讓 AI 協助整理網站名稱、介紹、文章或服務內容。

一鍵下載訪談包

下載後解壓縮，將文件上傳給 AI。

第一句話
我完全不會網站開發。我想請你先擔任我的網站訪談主持人，一次只問我一個問題，協助釐清網站的讀者、名稱、自我介紹、文章或服務內容。我不知道的地方請提供具體例子討論，最後整理出待我確認的網站內容準備稿。請先不要寫程式或公開內容。

05｜不用事先有 Logo：一起做品牌圖像

請 AI 提出三款 Logo 方向，選定後製作 favicon 和網站圖片。

  1. 從三款概念選一款。
  2. 確認 Logo 中文名稱正確。
  3. 請 AI 檢查 favicon 在小尺寸是否清楚。
  4. 確認圖片沒有冒充真實人物、客戶或場所。

06｜使用 GitHub Pages 發布網站（選用）

選擇 GitHub Pages 的學員，先完成以下設定：

  1. 開啟自己的網站倉庫。
  2. 點選上方 Settings。
  3. 從左側選單點 Pages。
  4. 找到 Build and deployment → Source，選擇 GitHub Actions。
  5. 請 AI 設定網站的自動建置與部署；等程式完成後，在 Actions 查看結果。
  6. 部署成功後，回到 Settings → Pages，點 Visit site 打開自己的網站。

完成確認：頁面出現 Your site is live at ...，而且 Visit site 能正常開啟。

如果畫面與教學不同，截圖給 AI，請它依畫面指引。

07｜準備 Cloudflare 帳號（非必要，但推薦）

非必要：不使用 Cloudflare，也能用 GitHub Pages 發布網站。

Cloudflare Pages 有什麼好處？哪些 GitHub Pages 也做得到？

GitHub Pages 與 Cloudflare Pages 都能發布網站。

功能Cloudflare PagesGitHub Pages 也有嗎？
私有 Repo 部署公開網站支援，原始碼可維持 Private。免費個人方案不支援私有 Repo 發布 Pages；公開 Repo 可用。Pro／Team 等適用方案另有支援。
自動更新網站Git 整合推送後自動部署。有。使用 GitHub Actions 或 GitHub Pages 發布來源。
PR／分支預覽Git 整合提供獨立預覽網址。可做到，但通常要自行配置預覽 Workflow 或其他服務，並非一般 Pages 預設功能。
自訂網域與 HTTPS支援 pages.dev 預設網址、HTTPS 和自訂網域。有。提供 github.io 預設網址、HTTPS 和自訂網域；兩者網域購買費用另計。
限制預覽觀看可另啟用 Cloudflare Access 保護 Preview。一般 Pages 無同等一鍵功能。企業方案有特定私有發布能力，但不等於一般 PR 預覽保護。
網站流量分析可選用 Web Analytics。可另行加入 Google Analytics 或其他分析工具；GitHub Pages 無同等內建訪客分析面板。
網址轉址／HTTP 標頭可用 Pages 的 _redirects 與 _headers 規則。部分可做到。Astro 可生成跳轉頁、設定其他服務，但 GitHub Pages 不直接提供等同的伺服器端規則功能。
指定頁面／路徑存取控制可另外配置 Cloudflare Access 或規則；不是自動的。一般免費 Pages 不提供按路徑的登入控管。企業私有 Pages 為不同使用場景。

選擇建議：公開原始碼可用 GitHub Pages；希望原始碼保留私人，選 Cloudflare Pages。私人倉庫不代表網站不公開。
