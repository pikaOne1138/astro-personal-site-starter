FROM ZERO TO A REAL WEBSITE · STUDENT SOP 01

從零開始，
把自己的網站做出來。

一份可以逐步照做的架站操作手冊：準備資料、選設計、交給 AI 建站、連接 GitHub 與 Cloudflare、用 PR 微調，最後親自確認發布。

這份教學同時是一份測試流程。照做時請勾選每一項；只要哪一步做不到，就記下畫面與錯誤，作為工作坊改進依據。

開始操作 ↓
這份手冊不會替你自動部署。

你需要自己的 GitHub 帳號、可執行程式碼的 AI 工具，以及自己真正想放上網站的內容。第一版建議用免費的 Cloudflare Pages 靜態託管。GitHub Pages 也可選。

進度勾選只保存在目前瀏覽器；不會上傳伺服器。

00
認識流程與成果

這是一份真正可以拿來測試的操作手冊。你會建立自己的獨立網站，而不是修改工作坊的展示站。

01
準備帳號與素材

確認 GitHub、AI 開發工具、網站文字、圖片、聯絡資訊。Cloudflare 可以晚一點再連接。

02
認識 GitHub 操作頁

學會分辨 Repo、Code、Branch、Pull requests、Actions、Settings，以及正式網站。

03
規劃網站並匯出 JSON

先選網站用途、首頁 Layout、配色、導航和 Section Patterns；把規劃器的 Site Brief JSON 保存好。

04
建立獨立網站原始碼

讓 AI 根據 Site Brief 產生 Astro 骨架，然後照選定 Layout 完成真正的設計與內頁。

05
將獨立網站放上 GitHub

自己的網站要使用自己的 Repository，不要推送到工作坊展示 Repo。

06
連接 Cloudflare Pages

推薦初次測試採 GitHub + Cloudflare Pages；也提供只用 GitHub Pages 的替代路線。

07
開 PR、看預覽、微調

所有修改先開 Branch/PR，檢查 Build、預覽網址和四種螢幕尺寸，再回報 AI 修正。

08
核准發布、驗收網站

親自確認後才 Merge。檢查網址、文章、搜尋、聯絡、手機、SEO，不以綠色 Build 當成完成。

09
日常更新、備份與還原

學會新增文章、修正網站、檢查部署記錄，以及如何透過 PR 撤回錯誤變更。

完成定義

你擁有獨立 Repository、真實可開的正式網站網址、可用的內頁與連結、可修改文章/內容、可看 PR 預覽並安全回復上一版；四尺寸 QA 與發布後健康檢查有實際紀錄。

00 / ORIENTATION

區分展示站與你的網站

工作坊公開的 12 款 Layout 是首頁構圖原型；40 種 Recipes 是局部構圖參考；Section Patterns 是多個 Blocks 組合成的整段；Blocks 是功能元件；Effects 是微動畫。它們不是同一件事。

重要：/starter/ 規劃器 目前只匯出 Site Brief JSON；匯出器能產生獨立 Astro 骨架，但選定版型的高保真移植、內頁補齊、圖片與正式服務串接仍需要 AI 開發與人工驗收。
01 / PREPARE

前置準備與帳號授權

先準備這些資料

GitHub 與 AI 工具怎麼連接？

在你選用的 AI 開發工具中，尋找 Connect GitHub / GitHub App / 授權 Repository 一類功能；按平台授權畫面選取帳號與授權範圍。不同 AI 工具的入口不同：若工具只有聊天功能，就需要搭配能實際執行終端機、修改檔案與提交 Git 的開發環境。

請先讓 AI 列出它實際能讀寫的 Repo，不要把「能看網頁」當成「已取得寫入授權」。密碼、Personal Access Token、Cloudflare API Token 不要貼給 AI，也不要寫進網站。

建立 GitHub 帳號 ↗官方註冊入口Cloudflare Dashboard ↗登入或建立帳號
01｜先讓 AI 檢查前置條件
我完全不會寫程式，要照著 Astro 架站工作坊建立自己的「獨立個人網站」。請先協助我確認：GitHub 是否已登入並授權你操作、是否有可編輯的程式碼工作環境、是否已準備網站文字/圖片，以及我選擇 Cloudflare Pages 還是 GitHub Pages。沒有授權的事情請告訴我應該在哪個官方介面按哪個選項；不要索取或顯示 API Token、密碼。請按「已完成／缺少／下一步」回覆，不要直接修改工作坊展示站。
02 / GITHUB MAP

GitHub 常用頁面對照

以下以「你自己的 Repository」為準。建站期間最常往返 Code、Pull requests、Actions、Settings。表格中的連結是官方示例或工作坊 Repo，不要誤以為是你未來個人網站的 Repo。

頁面你在這裡做什麼
New repository ↗建立自己網站的獨立原始碼倉庫
Code ↗找檔案、切換 Branch、看最新 Commit；連結為工作坊示範 Repo
Pull requests ↗看修改提案，開啟 Files changed、Conversation 與 Checks，最後人工核准 Merge
Actions ↗看 Build/Deploy 是否真的成功；點進失敗步驟讀錯誤 Log
Settings → Pages ↗只使用 GitHub Pages 時設定 GitHub Actions 發布來源（需自己 Repo 的管理權限）
Settings → Secrets and variables若真的使用需憑證的整合，設定 Secret；不能把密鑰直接寫進 Repo
Commits / History查看上次正常版本，為修正或還原建立新 PR

GitHub Actions 綠燈 = 這次工作流程成功，不等於 UI 已經肉眼驗收。

02｜請 AI 幫我整理網站素材
我要做一個 Astro 個人網站。類型是【知識／部落格 或 助人者／專業服務】。讀者是【填寫】，最重要的行動是【讀文章／聯絡／預約】。我已有的內容是【填寫】。請先整理：網站名稱與一句介紹、必需頁面、每頁需要的文字與圖片、哪些真實資訊不足、不可虛構的資料。不要替我編造證照、評論、服務成效、價格、聯絡方式或文章。
04 / ASSEMBLE

AI 建立獨立網站，不只生成首頁

請把 JSON 檔案交給能操作檔案的 AI 開發環境。核心命令是 node scripts/export-starter.mjs <site-brief.json> <新空資料夾>，但它只是第一階段：產生可以建置的網站骨架。

第二階段一定要完成

03｜根據 Site Brief 組裝網站
我已附上從 /starter/ 匯出的 Site Brief JSON。請先閱讀此 Repo 的 AGENTS.md、.ai/astro-starter-onboarding/SKILL.md、.ai/astro-site-assembly/SKILL.md、.ai/astro-layout-craft/SKILL.md、.ai/astro-editorial-layout-design/SKILL.md、.ai/astro-ui-craft/SKILL.md，以及現有 Blocks 與 Section Patterns Registry。驗證 JSON 後使用 node scripts/export-starter.mjs <site-brief.json> <新空資料夾> 產生獨立 Astro 網站；不要覆蓋原展示站。接著依我選的真實 Layout Prototype 做第二階段構圖移植（Hero 比例、資訊順序、圖文、手機重排），完成所有啟用內頁及真實連結，而不只換顏色。未配置的功能要隱藏或標示，不能假裝成功。請先列出建立的檔案、缺少的內容及完整建置計畫。
05 / REPOSITORY

建立自己網站的 GitHub Repo

使用 GitHub → New repository。建議用與品牌有關的英文名稱，例如 my-personal-site；新網站推到自己的 Repo。不要 Fork 後直接讓研究展示站的 CI 當作你的正式發布系統，要先確認獨立站的建置設定、網址與 Workflow。

驗收點

04｜建立自己的 GitHub Repository
請幫我將目前產生的「獨立 Astro 網站」放到我自己的 GitHub Repository，建議名稱【我的網站英文名稱】。先確認我是否授權 GitHub，以及現在目錄確實是獨立網站而不是工作坊展示倉庫。不得把研究展示站的 GitHub Pages 網址、base 路徑、PR 預覽 Workflow 原封不動帶過來。若需要我到 GitHub 建立新 Repository，請提供清楚的操作步驟；涉及刪除、公開敏感資料或覆蓋既有 Repo 必須先問我。
06 / HOSTING

連接 Cloudflare，讓 GitHub 自動部署

路線 A：Cloudflare Pages（本手冊建議先測這條）

Cloudflare Pages 的 Git 整合可對 PR/分支產生 Preview Deployment；請以 Cloudflare 實際顯示的網址為準。純靜態 Astro 不必為了發站就使用 D1、R2、SSR 或 Worker 後端。

Cloudflare 官方 Astro 教學 ↗ · 開啟 Dashboard ↗

路線 B：只使用 GitHub Pages（替代選項）

自己的 Repo → Settings → Pages → Build and deployment → Source：GitHub Actions。要使用適合獨立站的 Astro Build/Deploy Workflow；Repo 站一般要設定正確的 site 和 base，不能原樣沿用工作坊的 /astro-personal-site-starter/。一般 GitHub Pages 官方工作流程並不自動提供 PR 的線上預覽，這一點要額外驗證。

05｜設定 Cloudflare Pages
我要讓自己的獨立 Astro 靜態網站用 GitHub + Cloudflare Pages 發布。請閱讀 .ai/astro-starter-deploy/SKILL.md，先確認 Repo、靜態產出、Astro site/base 與部署分支。引導我在 Cloudflare Dashboard → Workers & Pages → Create application → Pages → Import an existing Git repository 授權 GitHub 並選對 Repo；Production branch 用 main、Build command 用 npm run build、Output directory 用 dist。請先驗證目前 Cloudflare 官方介面與方案仍適用。不得要求我把 Token 貼在聊天或 Commit，也不得宣稱網站已部署，直到我提供實際部署成功頁面或你查核到結果。
07 / ITERATE

微調循環：Branch → PR → Preview → 修正

不要直接請 AI 改 main。 每次微調只解決一組清楚的問題：例如「手機版標題超出畫面」、「服務卡太擠」、「CTA 指錯頁」。

06｜建立修改 PR 與預覽
請在我的「獨立網站 Repo」建立 feature branch 和 Pull Request，這次只修改【具體頁面或問題】。先讀 AGENTS.md 和相關 UI/部署 Skills，確認原有 Layout、Blocks 和 tokens。執行 npm run build，列出修改檔案與可能影響。若 Cloudflare Pages 已連上 GitHub，請提供真正成功部署的 Preview URL；若我走 GitHub Pages，請先確認是否有正確配置的 PR Preview，不能憑空捏造預覽網址。不要替我 Merge，我要先驗收。
07｜用畫面回饋做微調
我在 PR 預覽中發現以下問題：【貼上截圖、問題網址、裝置寬度及具體問題】。請只修正這次提到的地方，優先改善 Typography、Hierarchy、Grid、Spacing、Image treatment、CJK 與 RWD，不新增多餘效果或重做整個版型。檢查 1440、1280、768、390px，包含鍵盤與觸控、prefers-reduced-motion；重新 Build，把修正推到同一 PR。提供前後差異、測試證據與仍未驗收項目，等待我確認。
08 / RELEASE

三道品質關卡，然後才發布

① 內容準備度

頁面文案、照片授權、對外資訊、真實 CTA、SEO 設定是否足夠正式公開？

② 找得到資訊嗎？

找一位真人，不給提示，請他找文章、服務、聯絡與預約；觀察走錯的選單。

③ 上線健康檢查

Merge 後重新檢查正式 URL、HTTPS、頁面、搜尋、RSS、Sitemap、404、圖片與手機。

發布權限

PR 綠燈和預覽好看都不代表可自動 Merge；只能在本人確認後合併。

08｜正式上線前逐項檢查
我準備發布此獨立 Astro 網站。請按 .ai/astro-content-readiness/SKILL.md、.ai/astro-navigation-tree-test/SKILL.md、.ai/astro-starter-deploy/SKILL.md 檢查所有啟用頁面、真實內容、主 CTA、文章、Pagefind、圖片授權、SEO 與不同裝置。真人 Tree Test 要列成待我實際操作，不能假裝測過。請給我「已驗證／未驗證／阻擋上線」清單，並停在等待我明確同意合併 PR 的階段。
09 / MAINTAIN

內容更新、備份與還原

09｜合併後檢查與日常維護
我已明確核准這次 PR 可以合併。合併後請檢查 Cloudflare Pages 或 GitHub Pages 的最新 Production deployment，確認正式 URL 的首頁、內頁、手機選單、文章搜尋、RSS/sitemap/404 都可用。再依 .ai/astro-launch-health-check/SKILL.md 和 .ai/astro-site-maintenance/SKILL.md 提供下次寫文章、修改內容、備份、回復錯誤版本的簡明 SOP。不要把 GitHub Commit 當成外部表單、DNS 或電子報資料的完整備份。
HELP / WHEN SOMETHING BREAKS

遇到問題，先分辨發生在哪裡

現象先檢查
AI 說無法修改 RepoAI 是否真的具有 GitHub 寫入權限？它能否讀取、執行與提交檔案？
Build 紅燈GitHub Actions 或 Cloudflare Deployment 日誌的第一個具體錯誤；不憑印象亂改
Build 綠燈但圖片/樣式壞部署網址、Astro site/base、資產路徑、實際預覽的 CSS 載入
PR 沒有預覽連結是否真的配置 Cloudflare Pages Git 整合或獨立的 GitHub Pages PR Preview
搜尋不到文章正式 build 是否建立 Pagefind 索引、文章是否實際生成且可公開
預約/表單沒反應是否配置真正的外部服務；純前端展示不能假裝送出
發布後仍看到舊版先核對正式部署的 Commit 和 Deployment 狀態，再分析 CDN/快取

學員測試回報表

每遇到一個卡住的地方，請記錄「章節號碼、正在看的網址、看到的錯誤、實際畫面截圖、AI 工具名稱、能否自行解決」。我們要用真實困難修訂 SOP，而不是預設每個人都成功。
